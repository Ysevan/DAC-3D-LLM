# DAC-3D 常见问题

## 1. 文档定位

本文记录 DAC-3D 本地检测系统在安装、启动、离线检测、在线检测、模型推理、结果输出和数据库记录中的常见问题。内容依据当前目录 `C:\Users\xecat\DAC-3D-LLM\福特科\xxp_ui` 的源码与运行数据整理。

## 2. 启动与登录

### 2.1 启动后没有出现登录窗口怎么办？

先确认是否从 `xxp_ui` 目录运行 `python main.py`。系统依赖相对路径加载 `ui/login.ui`、`ui/ftk.ui` 和其他资源。如果从错误目录启动，PyQt 可能无法找到 UI 文件。

还应检查：

- PyQt5 是否安装。
- `window/login.py` 是否能正常导入。
- 当前 Python 版本是否与已安装依赖匹配。
- 控制台是否有导入错误或 DLL 加载错误。

### 2.2 普通用户和管理员有什么区别？

普通用户直接进入检测界面。管理员登录后可以看到设置入口和离线检测控件。若界面上没有“离线检测”或设置相关入口，通常说明当前是普通用户模式。

### 2.3 管理员密码错误怎么办？

当前版本管理员账号在 `window/login.py` 中本地校验。默认值为：

- 用户名：`admin`
- 密码：`123456`

如果现场版本修改过该文件，应以实际部署版本为准。

## 3. 离线检测

### 3.1 离线检测为什么找不到图片？

离线检测要求每个表面包含三张图，并能识别相机角色。文件名或目录中应包含：

- `焦后` 或 `DA3827093`
- `焦面` 或 `DA3562103`
- `焦前` 或 `DA3562117`

如果缺少任意一张，系统会跳过该表面。若同一位置只有 `surface1` 或只有 `surface2`，系统也不会形成完整样品。

常见问法：离线检测需要什么图片、离线检测图片怎么命名、为什么离线检测没有结果。标准回答是：每个样品位置必须同时具备上下两个表面，每个表面必须包含焦前、焦面、焦后三张图。

### 3.2 离线检测可以不连接硬件吗？

可以。离线检测只读取本地图像，不驱动相机、光源、Z 轴或 XY 平台。当前调试进程也支持离线硬件对象，因此本地电脑可用于演示和算法验证。

### 3.3 离线检测运行后没有结果怎么办？

按顺序检查：

1. 原图目录是否选对。
2. 目录下是否存在三相机完整图像组。
3. 文件名是否包含可识别的相机关键字。
4. 模型是否成功加载。
5. 控制台是否提示“未找到三相机原图组”或“表面不完整”。
6. `runtime/ftkpic/results` 下是否生成新的时间戳目录。

### 3.4 为什么只处理了部分样品？

系统只处理完整样品。完整样品要求同一 `pos` 同时具备 `surface1` 和 `surface2`，且每个 surface 都有焦前、焦面、焦后三张图。不完整分组会被跳过。

## 4. 在线检测

### 4.1 点击运行后设备没有动作怎么办？

主界面点击运行后，会向调试进程发送 `func="Scan"`。若设备没有动作，应确认：

- 调试进程是否启动。
- 调试进程是否完成硬件初始化。
- `ui_debug_queue` 是否正常传递消息。
- XY 载物台和 Z 轴控制卡是否连接成功。
- 是否处于离线检测模式。如果勾选了离线检测，系统不会驱动硬件。

### 4.2 在线检测必须连接数据库吗？

不是。数据库连接失败时，`DBController` 会进入离线模式，检测仍可执行。但历史记录、盘记录和缺陷追溯不完整。正式生产建议连接 MySQL。

### 4.3 为什么检测固定是 144 个点？

当前系统按 12 x 12 点位设计，主界面和扫描逻辑都围绕 144 个样品位工作。若工装盘数量变化，需要同步修改点位生成、界面按钮和统计逻辑。

## 5. 模型与推理

### 5.1 提示“模型未加载，使用随机结果进行模拟”怎么办？

这表示当前检测结果不可信，应立即排查模型加载。重点检查：

- `deploy/weights/best.pt` 是否存在。
- `torch` 是否可导入。
- `ultralytics` 是否可导入。
- `sahi` 是否可导入。
- CUDA 不可用时 CPU 是否可正常推理。

模型未加载时，系统可能生成随机合格或不合格结果，只能用于界面流程测试，不能用于质量判断。

### 5.2 GPU 不可用是否可以运行？

可以。代码会在 CUDA 不可用时使用 CPU，但推理速度会明显下降。若要做正式批量检测，建议使用支持 CUDA 的 PyTorch 环境。

### 5.3 为什么检测框很多，但结果仍然合格？

系统不会把所有检测框都当作不合格。检测框会经过区域规则和尺寸规则。以下缺陷可能被忽略：

- OUT 区缺陷。
- D 区中的 `splash` 和 `scratch`。
- 低于尺寸阈值的 `splash`。
- 被规则标记为 `ignore` 的缺陷。

应查看 `defect_detail.csv` 的 `is_qualified`、`is_ignored` 和 `reason` 字段。

### 5.4 为什么 D 区有很多缺陷但没有判不合格？

当前规则中 D 区主要对 `chipping` 做尺寸判定。D 区中的 `splash` 和 `scratch` 通常会被忽略。这是代码规则，不是 CSV 写错。

## 6. 图像融合

### 6.1 融合失败怎么办？

优先检查：

- 三相机图像是否都存在。
- 图像是否能被 OpenCV 正常读取。
- `homography_config.json` 是否存在。
- 配准矩阵是否匹配当前相机安装状态。
- 图像尺寸是否与标定时一致。

若配置文件不存在，代码会回退单位矩阵，但融合质量通常无法满足检测要求。

### 6.2 为什么焦前、焦面、焦后必须齐全？

当前融合流程使用三路图像共同生成融合图。焦面图像是参考图，焦前和焦后通过矩阵对齐到焦面。缺少任一路图像都会影响融合结果。

## 7. 结果文件

### 7.1 检测结果在哪里？

结果默认保存在：

```text
xxp_ui/runtime/ftkpic/results/<时间戳>/
```

重点查看：

- `检测结果/defect_detail.csv`
- `检测结果/defect_summary.csv`
- `检测结果/*_detect.jpg`
- `融合结果/fused_image_*.jpg`

### 7.2 没有 CSV 文件怎么办？

CSV 由图像处理进程在模型推理后生成。如果没有 CSV，应检查：

- 模型是否加载成功。
- 图像处理进程是否报错。
- `检测结果` 目录是否可写。
- 是否还没处理到完整的上下表面。

### 7.3 主界面历史记录为空怎么办？

历史记录依赖数据库。如果 MySQL 不可用，系统进入离线数据库模式，主界面仍可运行，但历史记录可能为空。应检查 MySQL 服务、账号密码和 `xxp` 数据库是否存在。

## 8. 硬件与控制

### 8.1 相机不可用怎么办？

检查：

- 海康相机 SDK 是否安装。
- 相机是否上电。
- USB 或网口是否连接。
- 相机序列号是否和代码中的 `DA3827093`、`DA3562117`、`DA3562103` 对应。
- 是否被其他软件占用。

### 8.2 光源无法控制怎么办？

当前光源串口配置集中在 `window/control/light.py`。重点检查：

- 串口是否为 `COM3`。
- 串口是否被其他软件占用。
- 波特率、数据位、校验位、停止位是否与控制器一致。
- 光源控制器是否上电。

### 8.3 运动控制卡连接失败怎么办？

Z 轴控制卡默认地址为 `192.168.0.11`。应检查：

- 控制卡供电。
- 网线连接。
- 本机 IP 是否与控制卡同网段。
- 防火墙是否阻止通信。
- `zauxdll.dll` 是否可加载。

### 8.4 载物台连接失败怎么办？

XY 载物台使用 `gclib` 连接 `10.0.0.100 --direct -s ALL`。应检查：

- 控制器 IP。
- `gclib` 是否安装或可导入。
- 网络直连状态。
- 现场控制器是否允许当前电脑连接。

## 9. 推荐排查顺序

出现问题时建议按以下顺序定位：

1. 确认是否从 `xxp_ui` 目录启动。
2. 查看控制台是否有导入错误。
3. 确认模型是否加载成功。
4. 离线检测时确认原图分组完整。
5. 在线检测时确认硬件初始化。
6. 查看 `runtime/ftkpic/results` 是否生成新目录。
7. 查看 `defect_detail.csv` 的 `reason` 字段。
8. 检查数据库是否进入离线模式。

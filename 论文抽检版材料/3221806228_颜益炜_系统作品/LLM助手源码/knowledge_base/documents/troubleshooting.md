# DAC-3D 故障处理指南

## 启动失败

如果 `python main.py` 后没有出现登录界面，先确认当前工作目录是 `xxp_ui`。系统使用相对路径加载 UI 文件，从错误目录启动会导致界面资源找不到。

继续检查 PyQt5、torch、opencv、ultralytics、sahi、pymysql 是否安装。

## 模型未加载

如果控制台出现“模型未加载”或“使用随机结果进行模拟”，当前检测结果不能用于质量判断。应检查：

- `deploy/weights/best.pt` 是否存在。
- PyTorch 是否可用。
- Ultralytics YOLO 是否可用。
- SAHI 是否可用。
- CUDA 不可用时是否可以 CPU 推理。

## 离线检测无结果

离线检测无结果时，先检查原图目录。每个表面必须包含三张图：

- 焦后或 `DA3827093`
- 焦面或 `DA3562103`
- 焦前或 `DA3562117`

同一位置必须同时有 `surface1` 和 `surface2`，否则不会形成完整样品。

## 融合结果异常

融合结果异常时，重点检查：

- 三相机原图是否齐全。
- 图像尺寸是否一致。
- `homography_config.json` 是否存在。
- 相机安装位置是否发生变化。
- 原图是否过曝、欠曝或严重模糊。

如果配置文件缺失，系统会回退单位矩阵，但融合质量可能不足以检测。

## 检测框很多但仍合格

这是正常现象。模型检测框会继续经过规则判定。OUT 区缺陷、D 区中的 splash/scratch、低于尺寸阈值的缺陷可能被忽略。

应查看 `defect_detail.csv` 中的：

- `is_qualified`
- `is_ignored`
- `reason`

## 数据库连接失败

数据库失败时系统会进入离线数据库模式。检测可继续，但历史记录和数据库追溯不完整。

默认数据库为：

```text
localhost:3306
root / 123456
database: xxp
```

可使用 `doc/mysql.sql` 初始化数据库结构，但正式部署时建议拆分出仅建表的 schema 文件，避免导入历史测试数据。

## 在线硬件无响应

在线硬件无响应时，按顺序检查：

1. 调试进程是否启动。
2. XY 载物台 `10.0.0.100` 是否可达。
3. Z 轴控制卡 `192.168.0.11` 是否可达。
4. 光源串口 `COM3` 是否被占用。
5. 三台相机是否能被 SDK 枚举。
6. 是否误勾选了离线检测。

## 结果目录没有更新

检测运行后，应在 `runtime/ftkpic/results` 下生成新的时间戳目录。若没有生成，说明图像处理进程没有收到有效输入或处理过程提前异常。

检查图像处理进程控制台输出，重点关注“未找到三相机原图组”“模型文件不存在”“图像处理过程中发生严重错误”等信息。

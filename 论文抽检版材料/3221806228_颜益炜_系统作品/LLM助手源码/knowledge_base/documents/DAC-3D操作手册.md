## 2. 系统用途

DAC-3D 本地检测系统用于对楔形片或同类圆形样品进行批量外观瑕疵检测。系统通过三相机采集焦前、焦面、焦后三路图像，完成图像配准与融合，再通过本地瑕疵检测模型识别缺陷，最终给出每个样品位置的合格或不合格结论。

系统支持两种运行方式：

- 在线检测：连接现场相机、光源、运动控制卡和载物台，执行完整 144 点位扫描。
- 离线检测：从本地文件夹读取已采集的三相机原图，不依赖现场硬件即可完成融合、推理和结果生成。

当前代码已具备本地离线运行能力。主程序启动调试进程时传入 `offline_hardware=True`，硬件不可用时会启用离线硬件替代对象；数据库不可用时也会进入离线数据库模式。

## 3. 系统组成

系统由三个常驻进程协同工作。

| 进程 | 入口 | 主要职责 |
| --- | --- | --- |
| 登录与主界面进程 | `openWindow()` | 登录、运行检测、展示 144 点位状态、查看历史和结果 |
| 调试与硬件控制进程 | `openDebug()` | 相机、光源、Z 轴、XY 载物台、扫描和对焦控制 |
| 图像处理进程 | `open_image_processor()` | 图像保存、配准融合、模型推理、CSV 输出和结果回传 |

进程之间通过 `multiprocessing.Queue` 传递消息，主要队列包括：

- `ui_debug_queue`
- `debug_ui_queue`
- `debug_image_queue`
- `image_debug_queue`
- `ui_image_queue`
- `image_ui_queue`

这种设计将界面、硬件动作和图像推理分离，避免图像处理或硬件等待阻塞主界面。

## 4. 启动流程

### 4.1 启动入口

在 `xxp_ui` 目录下运行：

```powershell
python main.py
```

启动后系统会创建退出事件、六个进程间队列，并依次启动图像处理进程、登录主界面进程和调试进程。

### 4.2 启动前检查

启动前建议确认以下项目：

- Python 环境已安装 PyQt5、torch、ultralytics、sahi、opencv、numpy、pillow、pandas、pymysql 等依赖。
- 本地模型文件存在，尤其是 `deploy/weights/best.pt`。
- `Algorithm/Regis_Fusion/homography_config.json` 存在。
- 离线检测时，原图目录中每个表面应包含焦前、焦面、焦后三张图。
- 在线检测时，相机、光源、运动控制卡和载物台已上电并连接。

## 7. 离线检测操作

### 7.1 适用场景

离线检测适用于以下情况：

- 现场硬件不在当前电脑上。
- 需要复查历史采集原图。
- 需要验证模型、融合算法或判定规则。
- 需要在本地电脑上独立演示系统能力。

离线检测不驱动相机、光源、Z 轴或 XY 平台，只读取本地原图并执行图像处理。

关键词：离线检测、本地检测、离线原图、三相机原图、图片命名、焦前、焦面、焦后、offline_detect_folder。

### 7.2 原图目录要求

离线目录可以是单层目录，也可以包含子目录。系统会递归扫描图片文件，支持常见扩展名：

- `.jpg`
- `.jpeg`
- `.bmp`
- `.png`
- `.tif`
- `.tiff`

每个表面必须凑齐三张图像：

| 相机角色 | 识别关键字 |
| --- | --- |
| 焦后 | `焦后` 或 `DA3827093` |
| 焦面 | `焦面` 或 `DA3562103` |
| 焦前 | `焦前` 或 `DA3562117` |

推荐命名方式：

```text
pos1_surface1_焦前.jpg
pos1_surface1_焦面.jpg
pos1_surface1_焦后.jpg
pos1_surface2_焦前.jpg
pos1_surface2_焦面.jpg
pos1_surface2_焦后.jpg
```

如果某个 `pos/surface` 缺少任一相机图像，系统会跳过该表面。只有同一位置同时存在 `surface1` 和 `surface2` 时，系统才会组成一个完整样品。

常见问法：离线检测需要什么图片、离线检测图片怎么命名、离线检测为什么找不到图片、离线检测需要焦前焦面焦后吗。答案是每个表面必须包含焦前、焦面、焦后三张图，推荐使用 `pos1_surface1_焦前.jpg`、`pos1_surface1_焦面.jpg`、`pos1_surface1_焦后.jpg` 这样的命名方式。

### 7.3 操作步骤

1. 使用管理员登录进入主界面。
2. 勾选“离线检测”。
3. 点击“选择原图目录”。
4. 选择包含三相机原图的文件夹。
5. 点击“运行”。
6. 等待状态提示从“离线检测中”变为“检测完成”。
7. 点击样品位置按钮查看结果图，或打开结果目录查看 CSV。

离线检测启动后，主界面会向图像处理进程发送 `offline_detect_folder` 消息。图像处理进程会在后台读取图像、执行融合和推理，并把 `Sample_detection_result` 消息返回给主界面。

## 8. 在线检测操作

### 8.1 适用场景

在线检测用于现场设备完整连接时的正式检测。它会驱动硬件完成整盘扫描，并对每个点位采集两组表面图像。

### 8.2 在线检测前置条件

开始在线检测前，应确认：

- 相机已经枚举并连接。
- 光源控制器串口可用。
- Z 轴控制卡网络可达。
- XY 载物台控制器网络可达。
- 样品和工装盘已固定。
- 焦面补偿数据可用。
- 模型文件已成功加载。

### 8.3 操作步骤

1. 使用管理员或用户模式进入主界面。
2. 确认设备初始化无明显报错。
3. 确认检测区域和样品盘状态。
4. 点击“运行”。
5. 系统创建新盘记录，重置 144 个点位状态。
6. 主界面向调试进程发送 `Scan` 控制消息。
7. 调试进程按蛇形路径采集图像。
8. 图像处理进程融合并检测每个样品。
9. 主界面持续刷新点位状态。
10. 检测完成后查看统计和详细结果。

### 8.4 停止检测

点击停止按钮时，主界面会向调试进程发送：

```python
{"type": "Control", "func": "Stop"}
```

停止后主界面会重新启用运行按钮、离线目录选择按钮和离线检测复选框。在线硬件动作是否立即停止，取决于调试进程当前执行到的运动或拍照阶段。

## 9. 图像处理流程

每个表面处理流程如下：

1. 接收三相机图像。
2. 保存焦后、焦面、焦前三张原图。
3. 读取 `homography_config.json` 中的两组变换矩阵。
4. 将焦后和焦前图像配准到焦面参考图。
5. 融合三路图像，生成融合图。
6. 对融合图执行圆形拟合和样品区域遮罩。
7. 使用 SAHI 切片推理调用 YOLO 模型检测瑕疵。
8. 将检测框映射到 A/B/C/D/OUT 区域。
9. 按区域和尺寸规则判断是否合格。
10. 保存检测图、明细 CSV 和区域统计 CSV。
11. 将上下两个表面合并为最终样品结果。

系统默认每个样品包含两个表面：

- `part_number=1`：下表面
- `part_number=2`：上表面

## 10. 输出文件

当前版本输出到：

```text
xxp_ui/runtime/ftkpic/results/<运行时间戳>/
```

典型目录结构：

```text
<运行时间戳>/
  离线原图/
  融合结果/
    pre_fusion_images/
    fused_image_pos1_surface1.jpg
    fused_image_pos1_surface2.jpg
  检测结果/
    pos1_surface1_detect.jpg
    pos1_surface2_detect.jpg
    defect_detail.csv
    defect_summary.csv
```

`defect_detail.csv` 记录单个缺陷级别信息。`defect_summary.csv` 记录每个样品、表面和区域的汇总统计。

## 13. 操作注意事项

- 正式检测前，应确认模型加载成功，不能依赖“随机结果模拟”。
- 离线检测目录必须包含完整三相机图像组。
- 若检测结果出现大量 OUT 区瑕疵，应检查圆形拟合和图像配准质量。
- 若 D 区中出现大量被忽略的 splash 或 scratch，不代表模型错误，因为当前规则中 D 区只对 chipping 做不合格判定。
- 数据库离线模式适合演示和调试，不适合正式追溯。
- 修改模型、阈值、配准矩阵后，应保存一组标准样品结果作为回归参考。

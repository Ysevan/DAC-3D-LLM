# DAC-3D IIM Assistant 部署指南

## 环境要求

- Python `3.10+`
- Node.js `20+` 与 npm，用于构建 React 前端
- 可写目录，用于持久化：
  - `knowledge_base/documents/`
  - `knowledge_base/vector_store/chroma/`
- 若启用真实 `Anthropic-compatible` provider，需要有效的 API Key 和网关配置
- 若需要解析 PDF，需要安装 `pypdf`

## 安装依赖

在仓库根目录执行：

```bash
python -m pip install -e .
python -m pip install -e ".[dev]"
cd frontend
npm install
```

## 配置环境变量

建议复制 `.env.example` 后按需修改。常用配置：

- `DAC3D_LLM_PROVIDER`
- `DAC3D_LLM_API_KEY`
- `DAC3D_LLM_API_BASE_URL`
- `DAC3D_LLM_MODEL_NAME`
- `DAC3D_VECTOR_STORE_TYPE`
- `DAC3D_EMBEDDING_MODEL_NAME`
- `DAC3D_EMBEDDING_DOWNLOAD_ALLOWED`
- `DAC3D_MOCK_MODE`
- `DAC3D_WEB_HOST`
- `DAC3D_WEB_PORT`
- `DAC3D_FRONTEND_DEV_URL`
- `DAC3D_GRADIO_HOST`
- `DAC3D_GRADIO_PORT`

## 启动方式

单条消息调试：

```bash
python app.py --message "当前检测状态是什么？"
```

启动 FastAPI + React Web UI：

```bash
cd frontend && npm run build && cd ..
python app.py
```

开发前端时可单独运行：

```bash
cd frontend
npm run dev
```

显式启动 CLI 或旧版 Gradio：

```bash
python app.py --cli
python app.py --gradio
```

## 知识库构建方式

### 命令行构建

将文档放入 `knowledge_base/documents/` 后执行：

```bash
python knowledge_base/build_kb.py
```

### Web 页面上传与构建

现在可以直接在 React Web 页面右侧 `设置` 面板上传文档并重建知识库：

1. 启动 `python app.py`
2. 打开 `http://127.0.0.1:8000`
3. 打开右侧 `设置`
4. 上传文档
5. 点击“创建 / 重建知识库”
6. 等待构建完成并查看最新构建记录

## 文档导入规则

知识库导入现在采用“内容探测优先，扩展名兜底”的策略，不再只依赖文件后缀。

当前支持按实际内容解析：

- Markdown / 纯文本
- PDF
- DOCX

默认切分窗口已调大到：

- `chunk_size=320`
- `chunk_overlap=80`

这意味着以下情况都可以正确处理：

- 文件名是 `.md`，实际内容是 PDF
- 文件名是 `.bin` 或 `.data`，实际内容是 DOCX
- 非 UTF-8 编码的中文文本文件

当前仍不支持：

- 旧版二进制 `.doc`
- 其他未知二进制格式

如果检测到旧版 `.doc` 或未知格式，Web 上传会直接拒绝，避免把二进制文件误当成文本切块。

## 检索策略

当前检索链路已升级为更稳的 hybrid retrieval：

- dense retrieval：向量相似度召回
- sparse retrieval：基于词项统计的稀疏召回
- rank fusion：融合 dense 和 sparse 排名
- section-aware rerank：章节名命中优先
- section dedupe：同一文档的同一章节只返回一个代表片段
- 全量上下文提交：检索命中的全部去重片段都会提交给 LLM，不再只传前几个结果
- 顺序降权：Prompt 中明确声明检索片段的展示顺序不代表优先级

这能显著减少“背景段落压过真正答案章节”的问题。

## 构建历史与日期显示

每次构建都会写入本地历史，并在 Web 页面显示：

- 最新构建时间
- 当前文档数
- 当前分块数
- 最近几次构建记录
- 是否来自 Web 上传
- 本次上传的文件名

持久化文件位置：

- `knowledge_base/vector_store/chroma/index.json`
- `knowledge_base/vector_store/chroma/build_history.json`

## DAC-3D 集成说明

- 当前阶段仍以 `integration/dac3d_client.py` 的 mock runtime 为主
- 若 `mock_mode=false` 且真实适配器未接入，会返回明确错误
- DAC-3D 协议访问必须继续收敛在 `integration/dac3d_client.py`

## 部署检查

建议在演示或交付前执行：

```bash
python -m compileall .
python -m pytest tests -q
python knowledge_base/build_kb.py
python app.py --message "DAC-3D 的设计原则是什么？"
```

若需要验证 Web 知识库管理流程，再执行：

1. `python app.py`
2. 上传一个测试文档
3. 点击“创建 / 重建知识库”
4. 确认页面出现新的构建日期和上传记录

## 常见问题

- 知识库不存在：执行 `python knowledge_base/build_kb.py`
- Web UI 无法启动：确认 `gradio` 已安装，或使用 `python app.py --cli`
- 上传后构建失败：检查文件是否为实际支持的内容格式，而不只是看后缀名
- 新文档没有命中：确认页面中的构建历史里已经出现本次构建日期
- Anthropic provider 报错：检查 API Key、Base URL、模型名配置
- 结果解释无法运行：确认 `DAC3D_MOCK_MODE=true`

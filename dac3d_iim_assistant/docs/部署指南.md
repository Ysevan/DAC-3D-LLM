# DAC-3D IIM Assistant 部署指南

本文档说明如何在本地部署、配置、运行和演示 DAC-3D IIM Assistant，并说明它如何与 DAC-3D 主系统 `xxp_ui` 通过本地状态文件和命令文件完成集成。

本指南面向两种演示形态：

1. LLM 智能检测助手原型 / 本地可演示系统：只运行助手 Web 页面，使用知识库、Mock DAC-3D 或本地状态文件完成问答、命令预览和结果解释。
2. 已嵌入 DAC-3D 主系统并可控制真实检测流程：从 DAC-3D 主系统按钮跳转到助手网页，助手读取主系统运行状态，并通过本地命令桥接触发离线检测、停止检测、查询状态等动作。

## 1. 系统定位

DAC-3D IIM Assistant 不是通用聊天机器人，而是面向 DAC-3D 工业检测流程的本地智能助手。核心能力包括：

- 自然语言操作：例如将“扫描 10mm×10mm 区域”转换为结构化扫描配置和 YAML 预览。
- 智能问答：基于 `knowledge_base/documents/` 中的 DAC-3D 文档回答参数、流程、设计原则和常见问题。
- 检测结果解读：读取检测结果结构化数据，解释缺陷类型、严重程度、阈值依据和处理建议。
- 操作建议：针对“样品反光太强怎么办”等问题给出基于知识库的操作指导。
- 实时状态查询：读取 DAC-3D 主系统写出的运行状态，回答“当前系统在做什么”“是否正在检测”等问题。
- 本地命令下发：通过文件桥接把助手生成的结构化命令传递给 DAC-3D 主系统。

## 3. 环境要求

推荐环境：

- Windows 10 或 Windows 11。
- Python 3.10。
- Node.js 20 或更高版本。
- npm。
- 可用的本地磁盘写权限。
- 可选：NVIDIA GPU、CUDA 驱动和 CUDA 版 PyTorch。

当前已验证的 GPU 环境示例：

```text
torch: 2.5.1+cu121
torchvision: 0.20.1+cu121
GPU: NVIDIA GeForce RTX 2060 with Max-Q Design
```

如果没有 GPU，助手本身仍可运行；DAC-3D 离线检测会退回 CPU，速度会明显变慢。

## 6. 环境变量配置

助手读取 `.env` 或系统环境变量。建议在项目根目录维护本地 `.env`，不要把真实 API Key 提交到仓库。

### 6.1 Mock 模式

Mock 模式不需要外网，不调用真实 LLM，适合本地演示基础流程：

```env
DAC3D_LLM_PROVIDER=mock
DAC3D_DAC_MOCK_MODE=true
DAC3D_LANGUAGE=zh
```

Mock 模式可演示：

- 意图识别。
- 结构化命令生成。
- YAML 预览。
- Mock 状态查询。
- Mock 检测结果解释。

Mock 模式不适合演示真实知识库问答质量。

### 6.2 TokenFlux / OpenAI-compatible 模式

如果使用 OpenAI-compatible 接口，例如 TokenFlux：

```env
DAC3D_LLM_PROVIDER=openai_compatible
DAC3D_LLM_API_BASE_URL=https://tokenflux.dev/v1
DAC3D_LLM_API_KEY=替换为你的真实Key
DAC3D_LLM_MODEL_NAME=gpt-5.5
DAC3D_LLM_TIMEOUT_SECONDS=60
DAC3D_LLM_RETRY_COUNT=2
DAC3D_LANGUAGE=zh
```

字段含义：

- `DAC3D_LLM_PROVIDER`：告诉助手使用哪种 LLM 适配器。
- `DAC3D_LLM_API_BASE_URL`：兼容 OpenAI Chat Completions 的服务端点。
- `DAC3D_LLM_API_KEY`：调用模型服务的密钥。
- `DAC3D_LLM_MODEL_NAME`：模型名称，必须是服务商实际支持的模型。
- `DAC3D_LLM_TIMEOUT_SECONDS`：单次请求超时时间。
- `DAC3D_LLM_RETRY_COUNT`：失败后的重试次数。

如果出现 `503 Service Unavailable`，通常不是助手代码错误，而是服务商端点、模型名、额度或临时服务状态问题。可先用最小请求测试模型是否可用。

### 6.3 Anthropic-compatible 模式

如果使用 Anthropic 兼容网关，例如 MiniMax Anthropic 兼容端点：

```env
DAC3D_LLM_PROVIDER=anthropic
DAC3D_LLM_API_KEY=替换为你的真实Key
DAC3D_LLM_API_BASE_URL=https://api.minimaxi.com/anthropic
DAC3D_LLM_MODEL_NAME=claude-3-5-haiku-latest

ANTHROPIC_API_KEY=替换为你的真实Key
ANTHROPIC_BASE_URL=https://api.minimaxi.com/anthropic
```

两套变量的区别：

- `DAC3D_LLM_*` 是本项目自己的统一配置，供 `config.py` 和 `rag/llm_client.py` 使用。
- `ANTHROPIC_*` 是 Anthropic SDK 常见兼容变量，供底层 SDK 或第三方工具读取。

建议两套同时配置，避免 SDK 和项目配置读取不一致。

### 6.4 会话记忆配置

统一 Agent 入口默认开启本地 JSON 历史记忆，文件位于：

```text
dac3d_iim_assistant/.tmp/conversation_memory/
```

每个 session 会写入独立 JSON，同时维护 `index.json` 用于历史搜索。LLM 每轮判断工具前会看到多层记忆上下文：当前页面短期历史、当前 session 最近对话、session 摘要和长期 JSON 索引检索结果。记忆只用于理解前文和用户偏好；实时状态、检测结果和执行命令仍以 `dac3d_*` 或 `machine_*` 工具返回为准。

常用配置：

```env
DAC3D_MEMORY_ENABLED=true
DAC3D_MEMORY_RECENT_TURNS=4
DAC3D_MEMORY_SEARCH_LIMIT=5
DAC3D_MEMORY_MAX_TURNS=200
DAC3D_MEMORY_INDEX_LIMIT=2000
```

## 7. 知识库文档准备

原始文档放在：

```text
C:\Users\xecat\DAC-3D-LLM\dac3d_iim_assistant\knowledge_base\documents
```

建议保留以下类型文件：

- DAC-3D 操作手册。

- DAC-3D 常见问题。

- DAC-3D 维护和排障说明。

- 大量重复文档。

知识库构建会读取这些文档并生成向量索引。网页端上传新文档后会自动保存并重建知识库；如果直接手动复制文件到该目录，则仍需点击“手动重建当前知识库”或执行命令行构建。

## 11. DAC-3D 文件桥接机制

助手和 DAC-3D 主系统通过本地 JSON 文件桥接。

状态文件：

```text
C:\Users\xecat\DAC-3D-LLM\dac3d_iim_assistant\.tmp\dac3d_runtime_status.json
```

命令文件：

```text
C:\Users\xecat\DAC-3D-LLM\dac3d_iim_assistant\.tmp\dac3d_assistant_command.json
```

命令回执文件：

```text
C:\Users\xecat\DAC-3D-LLM\dac3d_iim_assistant\.tmp\dac3d_assistant_command_ack.json
```

桥接流程：

1. DAC-3D 主系统启动后周期性写入 `dac3d_runtime_status.json`。
2. 用户在助手网页输入“当前系统在做什么？”。
3. 助手读取状态文件，而不是只从知识库检索。
4. 用户输入“选择 pre_fusion_images 下的图片进行离线检测”。
5. 助手生成 `start_offline_detection` 结构化命令。
6. 助手写入 `dac3d_assistant_command.json`。
7. DAC-3D 主系统轮询到命令后执行，并写入回执。
8. 助手后续可读取状态和结果进行解释。

这套机制避免了 UI 直接操作 DAC-3D 内部对象，保持了清晰的集成边界。

## 12. DAC-3D 相关环境变量

如果要让助手读取 DAC-3D 主系统实时状态，推荐配置：

```env
DAC3D_DAC_MOCK_MODE=false
DAC3D_ENDPOINT=file:///C:/Users/xecat/DAC-3D-LLM/dac3d_iim_assistant/.tmp/dac3d_runtime_status.json
DAC3D_COMMAND_PATH=C:/Users/xecat/DAC-3D-LLM/dac3d_iim_assistant/.tmp/dac3d_assistant_command.json
```

字段说明：

- `DAC3D_DAC_MOCK_MODE=false`：关闭 Mock DAC-3D 状态。
- `DAC3D_ENDPOINT=file:///...`：让助手从本地状态 JSON 读取 DAC-3D 运行状态。
- `DAC3D_COMMAND_PATH=...`：让助手把命令写到主系统会轮询的命令文件。

如果不启动 DAC-3D 主系统，也可以保留 Mock 模式做本地演示。

## 13. 自然语言到结构化命令

助手支持以下主要命令类型：

- `start_offline_detection`：启动离线检测。
- `start_online_scan`：启动在线扫描。
- `stop_detection`：停止当前检测。
- `query_status`：查询当前状态。
- `get_latest_result`：获取最近检测结果。
- `validate_offline_folder`：校验离线图片目录。
- `scan`：生成扫描配置预览。

示例 1：

```text
用户：扫描10mm×10mm区域
```

预期行为：

- 识别为 operation。
- 生成扫描配置预览。
- 不直接执行真实检测。
- 如果缺少分辨率、区域或模式，显示 `missing_fields` 和 `warnings`。

示例 2：

```text
用户：我想扫描一个25mm×25mm的楔形滤光片，步长10微米
```

预期回答：

```text
扫描范围：25mm × 25mm
步长：10μm
扫描模式：蛇形扫描
预计采集点数：6,250,000
预计扫描时间：约35分钟
是否需要生成配置文件并开始扫描？
```

示例 3：

```text
用户：选择C:\Users\xecat\DAC-3D-LLM\福特科\pre_fusion_images下的图片，进行离线测试
```

预期行为：

- 识别为 `start_offline_detection`。
- 提取离线图片目录。
- 写入命令文件。
- DAC-3D 主系统执行离线检测。

示例 4：

```text
用户：停止检测
```

预期行为：

- 识别为 `stop_detection`。
- 写入停止命令。
- DAC-3D 主系统停止在线或离线检测。

## 15. 在线扫描演示流程

在线扫描涉及真实设备或硬件控制，演示时应确认设备已连接并处于安全状态。

建议先输入预览命令：

```text

```

确认助手只生成配置，不直接执行。

如果要执行在线扫描，应使用明确执行语句：

```text
开始在线扫描10mm×10mm区域，步长20微米
```

上线演示前检查：

- 主系统是否连接 DAC-3D 硬件。
- 是否处于正确工作模式。
- 运动平台是否回零或处于安全位置。
- 目标区域是否已选定。
- 操作员是否确认扫描范围不会碰撞。

## 16. 检测状态查询

可用示例：

```text
当前系统在做什么？
现在检测到哪一步了？
当前是否正在运行？
现在是在线模式还是离线模式？

```

助手应优先读取 DAC-3D 状态文件。如果状态文件不存在或过期，助手应说明：

- 当前没有读取到 DAC-3D 实时状态。
- 可能是 DAC-3D 主系统未启动。
- 可能是文件桥接路径配置不一致。
- 可以切换到 Mock 模式只做原型演示。

## 17. 检测结果解读

可用示例：

```text
这个缺陷严重吗？
最近一次检测结果是什么？
请解释一下检测结果。
scratch 缺陷是否超过阈值？
pit 缺陷需要返工吗？
```

理想回答应包含：

- 缺陷类型。
- 置信度。
- 位置。
- 测量值。
- 严重度。
- 触发阈值或判定理由。
- 引用的知识库依据。
- 建议处理动作。

如果没有真实检测结果，助手应明确说明当前没有可解读结果，不能编造缺陷。

## 18. 操作建议演示

可用示例：

```text

```

预期回答风格：

```text

1. 降低 LED 功率至 30%-50%。
2. 适当增加曝光时间进行补偿。
3. 使用偏振片降低镜面反射。
4. 如果仍然饱和，尝试暗场模式。
5. 调整后重新采集一组样张确认灰度范围。
```

回答应基于知识库。如果知识库没有依据，应明确说明依据不足。

## 20. 常见问题排查

### 20.1 打开 `http://127.0.0.1:7860` 失败

可能原因：

- `python app.py` 没有启动。
- 端口被占用。
- 服务启动失败。
- 依赖未安装。

处理方式：

```powershell
python app.py
netstat -ano | findstr ":7860"
```

如果端口被占用，关闭旧进程后重新启动。

### 20.2 LLM 返回 503

可能原因：

- 服务商端点临时不可用。
- 模型名不支持。
- API Key 无效或额度不足。
- Base URL 配错。

处理方式：

- 确认 `DAC3D_LLM_API_BASE_URL`。
- 确认 `DAC3D_LLM_MODEL_NAME`。
- 使用最小请求测试模型。
- 临时切换到 `DAC3D_LLM_PROVIDER=mock` 完成本地演示。

### 20.3 问知识库问题却回答依据不足

可能原因：

- 没有构建知识库。
- 文档不在 `knowledge_base/documents/`。
- 文档格式解析失败。
- 上传后没有重新构建。
- 问题术语和文档术语差异太大。

处理方式：

```powershell
python knowledge_base\build_kb.py
```

然后重新提问，并检查回答中的引用来源。

### 20.4 DAC-3D 主系统闪退

可能原因：

- PyQt5 缺失。
- GPU/模型依赖不匹配。
- 主系统代码异常。
- 登录后 UI 事件处理异常。
- 离线检测队列或硬件队列异常。

处理方式：

- 在 PowerShell 中运行 `python main.py`，不要双击运行。
- 保留终端 traceback。
- 先确认 `python -c "from PyQt5.QtWidgets import QApplication"` 是否成功。
- 如果修改过主系统代码，重启主系统后再测试。

### 20.5 当前状态查询不实时

可能原因：

- DAC-3D 主系统没有启动。
- 主系统没有写状态文件。
- `DAC3D_ENDPOINT` 路径不正确。
- 助手仍处于 Mock 模式。

处理方式：

检查 `.env`：

```env
DAC3D_DAC_MOCK_MODE=false
DAC3D_ENDPOINT=file:///C:/Users/xecat/DAC-3D-LLM/dac3d_iim_assistant/.tmp/dac3d_runtime_status.json
```

检查状态文件是否更新：

```powershell
Get-Item .tmp\dac3d_runtime_status.json | Select-Object FullName,LastWriteTime
```

### 20.6 离线检测不能停止

可能原因：

- DAC-3D 主系统仍在运行旧代码。
- 停止命令没有写入命令文件。
- 主系统没有轮询到命令。
- 图像处理线程没有处理 stop 命令。

处理方式：

- 关闭并重新启动 DAC-3D 主系统。
- 输入“停止检测”。
- 检查命令文件和回执文件。
- 确认主系统终端没有异常 traceback。

# DAC-3D IIM Assistant 部署指南

本文档说明如何在本地部署、配置、运行和演示 DAC-3D IIM Assistant，并说明它如何与 DAC-3D 主系统 `xxp_ui` 通过本地状态文件和命令文件完成集成。

本指南面向两种演示形态：

1. LLM 智能检测助手原型 / 本地可演示系统：只运行助手 Web 页面，使用知识库、Mock DAC-3D 或本地状态文件完成问答、命令预览和结果解释。
2. 已嵌入 DAC-3D 主系统并可控制真实检测流程：从 DAC-3D 主系统按钮跳转到助手网页，助手读取主系统运行状态，并通过本地命令桥接触发离线检测、停止检测、查询状态等动作。

## 1. 系统定位

DAC-3D IIM Assistant 不是通用聊天机器人，而是面向 DAC-3D 工业检测流程的本地智能助手。核心能力包括：

- 自然语言操作：例如将“扫描 10mm×10mm 区域”转换为结构化扫描配置和 YAML 预览。
- 智能问答：基于 `knowledge_base/documents/` 中的 DAC-3D 文档回答参数、流程、设计原则和常见问题。
- 检测结果解读：读取检测结果结构化数据，解释缺陷类型、严重程度、阈值依据和处理建议。
- 操作建议：针对“样品反光太强怎么办”等问题给出基于知识库的操作指导。
- 实时状态查询：读取 DAC-3D 主系统写出的运行状态，回答“当前系统在做什么”“是否正在检测”等问题。
- 本地命令下发：通过文件桥接把助手生成的结构化命令传递给 DAC-3D 主系统。
- 多 Agent 协作：统一 Coordinator 负责入口和分派，QA、Control、Result、Machine、Memory、Skill、Safety 专家 Agent 负责各自工具组。
- 上下文工程：每轮只选择必要的状态、记忆、技能和安全策略，避免把全部历史、全部文档和全部工具说明直接塞进 prompt。

## 3. 环境要求

推荐环境：

- Windows 10 或 Windows 11。
- Python 3.10。
- Node.js 20 或更高版本。
- npm。
- 可用的本地磁盘写权限。
- 可选：NVIDIA GPU、CUDA 驱动和 CUDA 版 PyTorch。

当前已验证的 GPU 环境示例：

```text
torch: 2.5.1+cu121
torchvision: 0.20.1+cu121
GPU: NVIDIA GeForce RTX 2060 with Max-Q Design
```

如果没有 GPU，助手本身仍可运行；DAC-3D 离线检测会退回 CPU，速度会明显变慢。

```powershell
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else None)"
```

## 6. 环境变量配置

助手读取 `.env` 或系统环境变量。建议在项目根目录维护本地 `.env`，不要把真实 API Key 提交到仓库。

### 6.1 Mock 模式

Mock 模式不需要外网，不调用真实 LLM，适合本地演示基础流程：

```env
DAC3D_LLM_PROVIDER=mock
DAC3D_DAC_MOCK_MODE=true
DAC3D_LANGUAGE=zh
```

Mock 模式可演示：

- 意图识别。
- 结构化命令生成。
- YAML 预览。
- Mock 状态查询。
- Mock 检测结果解释。

Mock 模式不适合演示真实知识库问答质量。

### 6.2 TokenFlux / OpenAI-compatible 模式

如果使用 OpenAI-compatible 接口，例如 TokenFlux：

```env
DAC3D_LLM_PROVIDER=openai_compatible
DAC3D_LLM_API_BASE_URL=https://tokenflux.dev/v1
DAC3D_LLM_API_KEY=替换为你的真实Key
DAC3D_LLM_MODEL_NAME=gpt-5.5
DAC3D_LLM_TIMEOUT_SECONDS=60
DAC3D_LLM_RETRY_COUNT=2
DAC3D_LANGUAGE=zh
```

字段含义：

- `DAC3D_LLM_PROVIDER`：告诉助手使用哪种 LLM 适配器。
- `DAC3D_LLM_API_BASE_URL`：兼容 OpenAI Chat Completions 的服务端点。
- `DAC3D_LLM_API_KEY`：调用模型服务的密钥。
- `DAC3D_LLM_MODEL_NAME`：模型名称，必须是服务商实际支持的模型。
- `DAC3D_LLM_TIMEOUT_SECONDS`：单次请求超时时间。
- `DAC3D_LLM_RETRY_COUNT`：失败后的重试次数。

如果出现 `503 Service Unavailable`，通常不是助手代码错误，而是服务商端点、模型名、额度或临时服务状态问题。可先用最小请求测试模型是否可用。

### 6.3 Anthropic-compatible 模式

如果使用 Anthropic 兼容网关，例如 MiniMax Anthropic 兼容端点：

```env
DAC3D_LLM_PROVIDER=anthropic
DAC3D_LLM_API_KEY=替换为你的真实Key
DAC3D_LLM_API_BASE_URL=https://api.minimaxi.com/anthropic
DAC3D_LLM_MODEL_NAME=claude-3-5-haiku-latest

ANTHROPIC_API_KEY=替换为你的真实Key
ANTHROPIC_BASE_URL=https://api.minimaxi.com/anthropic
```

两套变量的区别：

- `DAC3D_LLM_*` 是本项目自己的统一配置，供 `config.py` 和 `rag/llm_client.py` 使用。
- `ANTHROPIC_*` 是 Anthropic SDK 常见兼容变量，供底层 SDK 或第三方工具读取。

建议两套同时配置，避免 SDK 和项目配置读取不一致。

### 6.4 会话记忆配置

统一 Agent 入口默认开启本地 JSON + Markdown 分层记忆，文件位于：

```text
dac3d_iim_assistant/.tmp/conversation_memory/
```

记忆结构参考 Hermes 的核心记忆/用户记忆/历史检索分层设计，并保留本项目要求的 JSON 存储优先：

- `MEMORY.md`：长期核心记忆，例如项目约定、稳定工作流和不会频繁变化的事实。
- `USER.md`：用户偏好，例如“执行前先看预览”“回答保持中文优先”。
- `sessions/*.json`：每个 session 的原始对话和结构化结果。
- `index.json`：跨 session 轻量搜索索引。
- `knowledge_notes/*.md`：主题化知识笔记，例如“反光处理”“离线检测流程”。
- `knowledge_index.json`：主题笔记索引。
- `procedures/*.md`：已审核流程记忆，每个文件包含 provenance frontmatter。
- `procedure_index.json`：流程记忆检索索引。
- `traces.jsonl`：每轮 Agent 输入、工具调用、记忆命中、安全审查和输出摘要。
- `memory_patches.json`：待审核的长期记忆写入建议，批准后才会进入 `MEMORY.md`、`USER.md`、主题笔记或流程记忆。

LLM 每轮判断工具前会看到多层记忆上下文：当前页面短期历史、核心 Markdown 记忆、当前 session 最近对话、session 摘要、主题知识笔记命中、流程记忆命中和长期 JSON 索引检索结果。`LocalMemoryProvider` 会把每轮交互记录为 trace，并把“以后/记住/纠正”等长期偏好生成待审核 memory patch；这保证长期记忆是可审计、可拒绝、可纠错的。Memory Agent 还可以通过 `conversation_memory_profile`、`conversation_memory_update`、`conversation_memory_patches`、`conversation_memory_approve_patch`、`conversation_memory_reject_patch`、`conversation_knowledge_notes`、`conversation_knowledge_read`、`conversation_knowledge_write`、`conversation_procedure_memories`、`conversation_procedure_read`、`conversation_procedure_write` 工具读写和审核这些记忆。Web UI 的“系统设置 -> 记忆补丁审核”会调用 `GET /api/memory/patches` 列出待审核补丁，并通过 `POST /api/memory/patches/{patch_id}/approve` 或 `POST /api/memory/patches/{patch_id}/reject` 完成批准/拒绝；批准后才会写入长期 Markdown 记忆。流程记忆也可通过 `GET/POST /api/memory/procedures` 读取或提出候选，候选批准后才会写入 `procedures/*.md`。记忆只用于理解前文和用户偏好；实时状态、检测结果和执行命令仍以 `dac3d_*` 或 `machine_*` 工具返回为准。

Memory Agent 的写入工具不会直接修改长期记忆：`conversation_memory_update`、`conversation_knowledge_write` 和 `conversation_procedure_write` 只生成 `memory_patches.json` 候选，必须经过批准后才会写入 `MEMORY.md`、`USER.md`、主题知识笔记或流程记忆。每个 patch 都带 `memory_status`、`trust_level`、`provenance`、policy decision 和 conflict 信息；`policy_memory` 需要特权审批，`tool_memory` 不能由 tool output 直接创建，`procedure_memory` 必须有 evidence trace，疑似 secret、跳过确认、自动执行等内容会被拒绝。检索命中会带 `source/trust_level/status`，`rejected`、`deleted`、`superseded` 记忆不会进入上下文。

常用配置：

```env
DAC3D_MEMORY_ENABLED=true
DAC3D_MEMORY_RECENT_TURNS=4
DAC3D_MEMORY_SEARCH_LIMIT=5
DAC3D_MEMORY_MAX_TURNS=200
DAC3D_MEMORY_INDEX_LIMIT=2000
DAC3D_MEMORY_CORE_CHAR_LIMIT=2200
DAC3D_MEMORY_USER_CHAR_LIMIT=1375
DAC3D_MEMORY_NOTE_CHAR_LIMIT=4000
```

### 6.5 命令确认生命周期配置

执行型 DAC 命令必须先生成 preview，再通过 Tool Gateway 校验和用户批准。确认 token 默认 300 秒过期，可以按现场操作习惯调整：

```env
DAC3D_COMMAND_CONFIRMATION_TTL_SECONDS=300
```

每个 pending preview 会记录 `preview_hash`、`confirmation_expires_at`、`lifecycle_state` 和状态事件。确认 token 绑定该 preview 的内容 hash，只能消费一次；过期、重复提交、修改 preview 或 token 不匹配都会 fail-closed。

### 6.6 Agent 技能系统

本地技能目录位于：

```text
dac3d_iim_assistant/skills/
```

每个技能目录至少包含 `SKILL.md`，也可以包含 `schema.json`、`examples.json`、命令模板、风险矩阵或参考说明。`SkillRegistry` 会执行：

```text
discover -> select -> progressive_disclosure -> tool_gateway
```

也就是先只读取技能元数据，根据当前任务选择相关技能，再按需把少量技能说明注入上下文。当前内置技能包括：

- `dac-command-preview`
- `dac-state-check`
- `dac-offline-inspection`
- `dac-result-explain`
- `dac-fault-recovery`
- `dac-memory-maintenance`
- `dac-safety-approval`
- `dac-context-engineering`

Skill Agent 暴露 `dac_skill_list`、`dac_skill_select`、`dac_skill_read`、`dac_skill_propose_patch`、`dac_skill_patches`、`dac_skill_approve_patch` 和 `dac_skill_reject_patch`。运行中发现某个流程反复需要补充时，Agent 只能把建议写入 `.tmp/conversation_memory/skill_patches.json`，由 Web UI 或 API 审核；批准记录不会自动修改生产 `SKILL.md`，实际合入仍需要人工或后续代码提交。技能说明只能补充流程知识，不能覆盖系统安全策略；涉及状态、结果、执行、记忆写入时仍必须调用对应受控工具。

### 6.7 Context Builder 配置

统一 Agent 入口每轮都会经过 `ContextBuilder`，执行：

```text
write -> select -> compress -> isolate
```

它会根据当前任务选择少量必要上下文：控制类任务会注入安全策略和 DAC 运行状态；状态、结果、设备异常类问题会注入压缩后的 runtime status；与流程相关的问题会按需加载匹配 skill；跨轮指代和用户偏好会进入多层记忆上下文。纯指导类问题不会无条件注入 idle 状态，避免上下文污染。每次响应的 `parsed_result.context_engineering` 会记录本轮实际使用的 sections、被排除的大块上下文和字符限制。

上下文现在还会带来源信任等级：

- `approved_policy`：内置安全边界和审核过的策略，可作为执行规则。
- `tool_output`：DAC 状态、结果、工具返回，只能作为 observation，不是指令。
- `retrieved_doc`：RAG/文档片段，只能作为证据数据，不能覆盖系统策略。
- `approved_memory`：长期记忆和历史偏好，只能帮助理解背景，不能授予工具权限或跳过确认。
- `user_input`：用户任务请求，可以表达目标，但不能关闭 `PolicyEngine`、`SafetyGuard` 或确认流程。

RAG prompt 会显式标记 `trust=retrieved_doc`、`can_instruct_agent=false`、`can_influence_tools=false`。Context Builder 渲染每段上下文时也会写入 `trust_level`、`can_instruct_agent`、`can_influence_tools`，并把疑似 prompt injection 文本记录到 `parsed_result.context_engineering.trust.injection_signals`。即使没有命中关键词，执行类副作用仍必须经过 Tool Gateway、路径白名单、命令生命周期和用户批准按钮。

常用配置：

```env
DAC3D_CONTEXT_SKILL_LIMIT=2
DAC3D_CONTEXT_CHAR_LIMIT=7200
```

### 6.8 Tool Gateway、PolicyEngine 与 Safety Guard 配置

DAC 控制、状态和结果工具现在经过 `DAC3DToolGateway`。网关提供 MCP-style 工具描述，并统一执行：

```text
preview_command -> validate_command -> require_confirmation -> submit_command -> read_status -> command_history
```

核心工具包括：

- `read_dac_status`
- `read_latest_result`
- `list_allowed_dirs`
- `preview_command`
- `validate_command`
- `submit_command`
- `cancel_pending_command`
- `read_command_history`

每个工具描述都会包含 MCP-style annotations：

- `readOnlyHint`
- `destructiveHint`
- `idempotentHint`
- `openWorldHint`

这些 annotations 只用于 UI 和未来 MCP client 的风险提示，不作为执行授权依据。项目同时提供轻量 `tool_gateway.mcp_adapter`，可把内部描述映射为 `inputSchema`、`outputSchema`、`annotations` 和 `x-dac3d` 元数据；真正的执行约束仍然只由 `PolicyEngine`、`SafetyGuard`、Tool Gateway validation 和 confirmation token enforcement 决定。

`tool_gateway.mcp_adapter` 还会生成 MCP-compatible capability manifest，内容包括 `tools`、只读 `resources`、可复用 `prompts`、本地 roots 和部署模式。它不是独立 MCP server，也不会替换当前 FastAPI/CLI/Agent SDK 路径；作用是让未来 MCP client 或 OpenAI Agents SDK orchestration layer 可以用同一份发现数据理解 DAC-Agent Runtime。Agent 工具名是 `dac_mcp_manifest`，Web 入口是 `GET /api/mcp/manifest`。

`PolicyEngine` 是代码化的生产安全策略层，会在每次 Tool Gateway 调用前 fail-closed 检查工具注册、输入 schema、高风险确认、destructive 工具确认、open-world 私有上下文、绕过确认文本、未知/禁止工具、command submit 必需的 `preview_id`/`confirmation_token`/validation，以及 memory write 和 skill patch 是否只能作为待审核补丁。`SafetyGuard` 会继续检查风险等级、缺失字段、运行时忙碌状态、路径白名单和明显的 prompt-injection / 绕过确认语句；底层 `PathPolicy` 会对用户路径做 canonicalize，并阻止 `..`、symlink escape、UNC/network path、allowlist 外路径、secret 文件读取和 command output 覆盖配置文件。执行类命令必须先有 pending preview，并通过 `preview_id` 与确认 token 校验后才会提交到 embedded bridge、file command bridge 或 mock runtime。命令生命周期会记录 `preview_created`、`validation_passed`、`awaiting_confirmation`、`confirmed`、`submitted`、`expired`、`cancelled` 等状态；确认 token 绑定 `preview_hash`，有 TTL，只能消费一次。Web UI 会把可提交的 pending preview 渲染为“批准执行”按钮，并显示生命周期状态、TTL 和过期时间；点击按钮会调用 `/api/commands/approve`，由后端继续当前 session 的 `submit_command` 流程，避免让操作员重复输入确认文本。

路径敏感命令默认允许：

- `dac3d_iim_assistant/.tmp/`
- `福特科/pre_fusion_images/`
- `福特科/xxp_ui/runtime/`

如需覆盖路径白名单：

```env
DAC3D_ALLOWED_DIRS=C:\DACData\Offline,D:\DACRuntime
```

命令桥写入路径有独立的 command output allowlist。默认会使用 file bridge 的命令文件所在目录和助手 `.tmp/`；生产环境建议显式收紧：

```env
DAC3D_COMMAND_OUTPUT_DIR=C:\DACRuntime\CommandBridge
```

生产环境建议只配置实际允许读取的离线检测目录和 DAC 运行目录，不要把整盘根目录加入白名单；命令输出目录也不要指向项目配置目录、用户主目录或整盘根目录。

### 6.9 Trace Logger 与 Eval Runner

统一 Agent 入口会额外写入 append-only trace：

```text
dac3d_iim_assistant/.tmp/conversation_memory/agent_traces.jsonl
```

每条 trace 记录 session、用户问题、意图、工具调用、命令预览 ID、风险决策、批准状态、最终回复和 memory patch ID。`TraceLogger` 会对 `api_key`、`authorization`、`password`、`secret`、`token` 等字段做基础脱敏，因此确认 token 不会明文进入 trace。

本地评测用例位于：

```text
dac3d_iim_assistant/evals/cases/
```

当前回归集至少包含 20 个确定性用例，覆盖状态查询、命令预览、批准提交、记忆写入候选、prompt injection 拦截，以及多种“绕过确认 / 直接写 command.json / ignore system rules”的 security red-team 变体。

当前回归集覆盖：

- `state_query`
- `command_preview`
- `confirmation_required`
- `prompt_injection`
- `memory_write`

可通过 API 运行：

```bash
curl -X POST http://127.0.0.1:7890/api/evals/run \
  -H "Content-Type: application/json" \
  -d '{}'
```

也可以在 Web UI 的“系统设置”中点击“运行评测”。评测报告会返回每个 case 的通过状态、失败检查项和关联 trace id，用于把 trace -> eval -> 回归报告变成持续改进闭环。

Trace-to-eval 草稿生成接口：

```bash
curl -X POST http://127.0.0.1:7890/api/evals/drafts \
  -H "Content-Type: application/json" \
  -d '{"limit": 5}'
```

该接口会把最近或指定 trace 转成待审核 JSON 草稿，保存到：

```text
dac3d_iim_assistant/evals/drafts/
```

草稿带有 `draft: true`、`source_trace_id`、预期意图、工具调用、风险等级和确认要求等字段，但不会自动加入 `evals/cases/`，必须人工审核后才可提升为正式回归用例。

命令文件：

8. 助手后续可读取状态和结果进行解释。

这套机制避免了 UI 直接操作 DAC-3D 内部对象，保持了清晰的集成边界。

## 20. 常见问题排查

### 20.1 打开 `http://127.0.0.1:7860` 失败

可能原因：

- `python app.py` 没有启动。
- 端口被占用。
- 服务启动失败。
- 依赖未安装。

处理方式：

```powershell
python app.py
netstat -ano | findstr ":7860"
```

如果端口被占用，关闭旧进程后重新启动。

### 20.2 LLM 返回 503

可能原因：

- 服务商端点临时不可用。
- 模型名不支持。
- API Key 无效或额度不足。
- Base URL 配错。

处理方式：

- 确认 `DAC3D_LLM_API_BASE_URL`。
- 确认 `DAC3D_LLM_MODEL_NAME`。
- 使用最小请求测试模型。
- 临时切换到 `DAC3D_LLM_PROVIDER=mock` 完成本地演示。

### 20.3 问知识库问题却回答依据不足

可能原因：

- 没有构建知识库。
- 文档不在 `knowledge_base/documents/`。
- 文档格式解析失败。
- 上传后没有重新构建。
- 问题术语和文档术语差异太大。

处理方式：

```powershell
python knowledge_base\build_kb.py
```

然后重新提问，并检查回答中的引用来源。

### 20.4 DAC-3D 主系统闪退

可能原因：

- PyQt5 缺失。
- GPU/模型依赖不匹配。
- 主系统代码异常。
- 登录后 UI 事件处理异常。
- 离线检测队列或硬件队列异常。

处理方式：

- 在 PowerShell 中运行 `python main.py`，不要双击运行。
- 保留终端 traceback。
- 先确认 `python -c "from PyQt5.QtWidgets import QApplication"` 是否成功。
- 如果修改过主系统代码，重启主系统后再测试。

### 20.5 当前状态查询不实时

可能原因：

- DAC-3D 主系统没有启动。
- 主系统没有写状态文件。
- `DAC3D_ENDPOINT` 路径不正确。
- 助手仍处于 Mock 模式。

处理方式：

检查 `.env`：

```env
DAC3D_DAC_MOCK_MODE=false
DAC3D_ENDPOINT=file:///C:/Users/xecat/DAC-3D-LLM/dac3d_iim_assistant/.tmp/dac3d_runtime_status.json
```

检查状态文件是否更新：

```powershell
Get-Item .tmp\dac3d_runtime_status.json | Select-Object FullName,LastWriteTime
```

### 20.6 离线检测不能停止

可能原因：

- DAC-3D 主系统仍在运行旧代码。
- 停止命令没有写入命令文件。
- 主系统没有轮询到命令。
- 图像处理线程没有处理 stop 命令。

处理方式：

- 关闭并重新启动 DAC-3D 主系统。
- 输入“停止检测”。
- 检查命令文件和回执文件。
- 确认主系统终端没有异常 traceback。

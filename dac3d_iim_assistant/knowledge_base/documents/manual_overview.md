# DAC-3D 系统总览

## 系统定位

DAC-3D 是一套本地部署的三相机楔形片瑕疵检测系统。系统通过 PyQt 桌面界面管理检测流程，通过本地模型完成瑕疵推理，通过本地目录和 MySQL 保存结果。

当前交付目录位于 `C:\Users\xecat\DAC-3D-LLM\福特科\xxp_ui`。它包含源码、UI 文件、模型权重、硬件 DLL、配准矩阵、数据库脚本、离线原图和历史检测结果。

## 核心能力

系统具备以下核心能力：

- 在线 144 点位整盘检测。
- 本地离线检测。
- 三相机焦前、焦面、焦后图像采集。
- 三图配准与融合。
- SAHI + YOLO 本地瑕疵检测。
- A/B/C/D/OUT 区域判定。
- 合格和不合格结果输出。
- 检测图、融合图、明细 CSV 和统计 CSV 保存。
- MySQL 历史记录写入。
- 数据库不可用时离线运行。
- 硬件不可用时离线硬件替代运行。

## 进程结构

系统入口 `main.py` 启动三个进程：

- 主界面进程：负责登录、操作、显示和历史查看。
- 调试进程：负责硬件控制、扫描、拍照和对焦。
- 图像处理进程：负责融合、推理、结果生成和结果回传。

进程间通过队列通信。主界面不直接执行模型推理，也不直接访问硬件动作细节。

## 主要数据流

标准检测数据流如下：

1. 操作员点击运行或选择离线检测目录。
2. 主界面创建盘编号并发送检测消息。
3. 在线模式由调试进程采集三相机图像；离线模式由图像处理进程读取本地原图。
4. 图像处理进程保存原图并执行三图融合。
5. 本地模型检测 `splash`、`scratch`、`chipping` 等瑕疵。
6. 系统按区域和尺寸规则判断合格性。
7. 主界面接收样品结果并刷新 144 点位状态。
8. 系统输出结果图和 CSV，并在数据库可用时写入历史。

## 本地部署特点

当前系统不依赖云端推理。模型权重位于本地目录，默认使用 `deploy/weights/best.pt`。如果 CUDA 不可用，系统可以回退 CPU，但推理速度会降低。

离线检测是当前系统最稳定的本地演示入口。只要给定完整三相机原图组，即可在无硬件环境下验证融合和瑕疵检测流程。

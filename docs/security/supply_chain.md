# DAC-3D-LLM Supply Chain Security

## Current State

- Python dependencies are declared in `dac3d_iim_assistant/pyproject.toml` with minimum version constraints. There is no Python lockfile yet, so CI must run vulnerability checks against the resolved environment.
- Both React frontends use npm lockfiles: `dac3d_iim_assistant/frontend/package-lock.json` and `dac3d_iim_assistant/ui2/package-lock.json`.
- The assistant now packages the runtime `memory`, `security`, and `tracing` modules so editable and wheel installs include the security layer.
- Git LFS is required for large DAC-3D images and model artifacts. Do not replace LFS-managed assets with pointer files or regenerated local binaries.

## Checks Added

- Unit and security regression tests: `pytest tests -q`.
- Python syntax check: `python -m compileall .`.
- Dependency audit: `pip-audit` for Python and `npm audit --audit-level=moderate` for each frontend.
- Static security scan: `scripts/security_static_scan.py` checks for obvious hardcoded secrets, `shell=True`, unsafe `pickle`, unsafe `yaml.load`, Python/JavaScript eval, and React `dangerouslySetInnerHTML`.
- Static analyzers in CI: `ruff` and `bandit`.
- Frontend build checks: `npm ci` and `npm run build` for both `frontend` and `ui2`.
- Agent/eval smoke: `pytest tests/test_agent_runtime.py tests/test_security_evals.py -q` and `python -m evals.run_security_evals`.

## CI Run

The GitHub Actions workflow `.github/workflows/security.yml` runs on pull requests and pushes. It installs Python and Node dependencies from declared manifests, runs tests, audits dependencies, performs static scanning, and builds both frontends.

New CI-only dependencies:

- `pip-audit`: Python dependency vulnerability audit.
- `ruff`: fast Python lint and unsafe-code hygiene checks.
- `bandit`: Python security static analysis.

These are not runtime dependencies and are installed only in the security job.

## Known Gaps

- Python dependencies are not locked. A future hardening pass should add a reproducible lockfile generated by a project-approved tool.
- The current static scanner is intentionally lightweight and pattern-based. It should complement, not replace, reviewed dependency updates and dedicated secret scanning in protected CI.
- Security evals are currently fail-closed red-team cases. A future pass should connect them to richer model/tool execution traces once production eval infrastructure is available.
